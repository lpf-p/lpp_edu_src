## §1 EduSRC / 教育专供打法（案例库验证命中率最高）

1. **一站式服务大厅突破靠信息收集，不靠爆破**：需要教师 `gh`（工号）、`sfz`（身份证）、学生 `sfz`/`xh`（学号）。来源：`site:*.edu.cn` 搜学校公告 PDF——生源地填报通知、助学金初审表、获奖名单，文件里直接带学号+身份证格式样本。**相关：`artifact-intel-guide.md` G/H 组文档字典。**
2. **验证码回显 → 任意密码重置（铜陵职院案例）**： forget 接口输入收集来的 QQ 邮箱 → `getUserNumByBindMail` 响应回显**学号** → `sendMailGetCode` 响应 `"data":"155064"` **直接回显验证码** → 改密接管。教育自研平台重置链路必须逐包看响应 `data` 字段。**相关：`password-reset-test.md`。**
3. **弱口令 + 统一认证旁路**：教务/诊改/数据平台常挂在 `:18703`、`:8088` 等高位端口的自建系统上，从学校主站子页面跳转发现（"数据分析平台""数据填报"入口）。
4. **某证书站高危模板**：Vue 站 → JS 路径去 GitHub 搜源码 → 认出芋道(yudao)框架 → 去官方演示站抓包拿接口路径 → 拼回目标 `/api/admin-api/infra/file-config/page` 未鉴权 → **OSS accessKey/accessSecret 直接落地高危**。框架认出 = 接口全知道。**相关：`js-reverse-guide.md` + `middleware-unauth-test.md`。**
5. **高校人事系统水平越权**：人事→我的卡片→个人信息，改请求看他人身份证号；自研 OA 越权普遍。

## §2 企业 / 厂商场景高频打法

1. **电商收货地址越权（经典老但常收）**：地址管理增/改/删三口逐个替换 id 差分；方法论：**养成保存数据包的习惯**——A 页面不越权不代表 B 页面不越权，参数就是线索。**相关：`idor-test.md`。**
2. **限制购买/首单优惠绕过**：活动标"仅限一次"→ 不支付前**多次创建订单**即破；PC 端 + 手机端双开窗口各下一单。学生优惠/特价服务器类活动重点测。
3. **重置密码分步验证**：验证码校验那一步的响应包看返回值，`true`/状态字段可改则跳步直进设新密。
4. **OAuth2.0 绑定劫持（第三方登录接管）**：登录+绑定处抓三段 302：authorize → weibo 回调带 `code` → 站点 callback。**第三个包（站点 callback?code=xxx）谁打开谁绑定**——发给受害者打开即绑攻击者微博，随后攻击者"微博登录"直接进受害者账号。绑定/快捷登录口必测 callback code 是否一次性、是否校验会话。
5. **邮箱 HTML 注入**：收款方式/昵称等自由文本字段支持 HTML（含 `<h1>`、链接），通知邮件渲染成钓鱼页 → 中危可交。
6. **小程序云存储上传**：用户反馈/头像上传处传 html 且落根目录可解析 → 存储型 XSS + 覆盖他人文件（易车案例，定高危）。
7. **弱口令不是万能钥匙但要先摸**：visionplus.vivo.com、麦当劳供应商站等按"认领企业 → 查其采购/外包系统 → 默认口令"。**注意范围**：供应商/第三方资产可能被厂商判"不在奖励范围"（麦当劳案例被忽略）——先确认域名归属再动手。

## §3 通用系统 / Nday 批量（FOFA 定位 + POC 直打）

案例库中大量报告遵循同一模板：**测绘语法定位 → 同套系统批量 → POC 命中**。高频出现的系统指纹：

| 系统 | 打法 |
|------|------|
| 蓝凌 Landray EIS | `app="Landray-EIS智慧协同平台"` SQL 注入 |
| 用友 U8 / NC | U8 `KeyWordReportQuery` 注入；NC `disp=/WEB-INF/web.xml` 任意文件读取 |
| 致远 OA / 通达 OA | 组合漏洞 RCE；通达发邮件/问答处存储 XSS（`<img src=x onerror=eval(atob(...))>`） |
| 若依 RuoYi | `admin/admin123` 默认口令 → 后台 RCE（智慧养老案例） |
| 宇视 ISC | `LogReport.php?action=execUpdate&fileString=x;id>xx.txt` |
| 好视通云会议 | `upLoad2.jsp` 任意上传 / `toDownload.do?fileName=../` 任意读取 |
| 安美数字酒店宽带 | `server_ping.php` ip 参数命令执行 |
| DedeCMS 5.7.106 | ShowMsg 函数反射 XSS，近 20 处，量多但鸡肋 |
| 帝国 CMS 7.5 | 任意文件包含；某博 CMS `download.php` base64 url 文件读取 |
| ueditor | `getContent.php/.asp/.jsp/.ashx` SSRF/XSS |
| phpBB/74cms/Finecms/zzcms | 后台 CSRF 无 token（多为 CVE 复现交 CNVD） |
| discuz 3.2x | 通用 SSRF（大厂站也中过） |
| 锐捷锐易网关 / Xbrother 动环 | 默认弱口令 → CNCERT 通报模板 |

**相关：`nday-watchlist-2026.md`、`middleware-unauth-test.md`、`src-platform-and-search.md`（CNVD/CNCERT 通报提交模板也在案例库中有现成样例）。**

## §4 专项技巧补充（案例库独有，rules 未覆盖的细节）

1. **无回显 SSRF 判活**：avatar 等外链图片参数接 dnslog，`#` 注释原 URL；对比响应**时长差**（0.3s vs 超时）+ dnslog 记录双确认。
2. **XSS 过滤绕过——`/:` 注释拼接**：过滤器把非法片段变注释时，用 `</:>1><</:button formaction=alert(1)` 让注释后的内容拼接生效（某鹅邮箱附件 html 存储型实战）。
3. **报告结构模板（案例库通用骨架）**：漏洞名称（目标+类型）→ 资产来源（FOFA/鹰图语法截图）→ 复现步骤（原始数据包逐条）→ 危害说明 → 平台（EDUSRC/CNVD）。正式报告仍只认 `rules/vuln-report-format.md`。
4. **前端验证码刷新**：验证码 4/5 位纯数字 + 前端刷新 = 爆破前提（当当案例），补天专属常见高危。
5. **通杀批量化**：认出外包商统一系统（如甲鼎就业平台 `title="就业"&&body="甲鼎"`）→ 鹰图/FOFA 全量 → 一个漏洞点多站通杀，逐站出报告。
