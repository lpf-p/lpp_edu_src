# SRC 案例复盘与报告写法（思路学习）

**定位**：怎么把「抓包改个参数」变成「能定高危、能拿赏金」的报告。本篇是**思路与模板**，具体格式以 `rules/vuln-report-format.md` 为准（那里是官方版式，本篇是实战心法，不重复字段）。

---

## 一、挖洞全流程（可复制的节奏）

来源：真实 SRC 实战复盘（状态篡改绕过审核，定级高危、赏金 1000）。

```
1. 选平台：大厂 SRC 审核严、重复多；补天/漏洞盒子等第三方众测，企业站点杂、逻辑漏洞常年泛滥 → 新手蹲这里出分稳
2. 选目标：专攻「状态流转类」功能 —— 审批/审核后台、订单支付退款、用户越权、前端限制后端不校验的接口
3. 挖洞：登录普通账号，正常操作抓包 → 改关键参数 → 看后端放不放
4. 写报告：固定模板，审核基本必过
```

**心法**：逻辑漏洞是冲高额赏金的主力——分值高、难度低、重复洞少；XSS/注入卷且难上高危。

## 二、经典案例：状态篡改绕过审核（审批系统）

**流程**：用户提交申请 → 管理员审核 → 流程生效（标准「提交→待审核→通过」状态机）。

**漏洞**：`/api/apply/submit` 的 `status` 字段由前端传，后端没权限校验。

```http
# 正常：status=0 待审核
POST /api/apply/submit
{"apply_id":"20260513001","user_id":"668899","status":0,"reason":"业务测试申请"}

# 篡改：直接改成 1 通过，无需管理员
POST /api/apply/submit
{"apply_id":"20260513001","user_id":"668899","status":1,"reason":"业务测试申请"}
# → 系统判定审核通过、立即生效，绕过管理员
```

**本质**：这就是 `logic-test.md` §5.1 状态机绕过 + `idor-test.md` 信任前端传参的具象化——把「待审核」状态字段当成了**用户可控输入**。

**同类高发**：订单状态（待付款→已付款）、退款状态、会员等级字段、审核标志位、任何 `status`/`state`/`passed`/`is_xxx` 布尔/枚举字段。

## 三、可直接套用的报告模板（七字段）

> 合规版式见 `rules/vuln-report-format.md`，这里给实战写作骨架。

```
【漏洞标题】某 XX 系统存在 XX 逻辑漏洞，可绕过 XX 直接 XX
【漏洞等级】高危 / 中危 / 低危（只认 format，不自己定）
【漏洞描述】接口 + 缺失的校验 + 攻击者可做什么 + 危害
【复现步骤】1.登录 2.抓包 3.改参 4.重放 5.看结果（可复现、可定性即停）
【影响范围】能被滥用的具体后果（批量/越权/绕过审核/数据泄露）
【修复建议】后端禁止用户控状态字段 / 加权限校验 / 强制流程流转 / 加审计日志
【漏洞证明】抓包截图（改前改后对比）+ 业务生效截图，敏感信息打码
```

**写报告的三个要点**（同样的洞，写得好更容易定高危）：
1. **描述说清「根因」**：不是「能改 status」，是「status 由前端传、后端无权限校验」
2. **复现步骤可抄**：别人照做能复现，审核才认
3. **影响说具体**：别写「危害极大」，写「可批量伪造审批记录、绕过管理员」

## 四、洞链思维（把小洞串成高危）

单个中危往往上不了高危，**串成链才行**。已知链（详见 `idor-test.md` §组合利用 + `nday-watchlist-2026.md` §3）：

| 链 | 路径 |
|---|---|
| 越权 + 文件下载 | 改文件 ID 下别人合同/证件 |
| 越权 + XSS | 给管理员发 payload 偷 Cookie 进后台 |
| 越权 + 文件上传 | 低权限传 webshell → RCE |
| 未授权 + 状态篡改 | 跳过审核/支付直接生效（本文案例） |
| 验证码缺陷 + 账号枚举 | 无限制暴破出账号 |

**报告里如何呈现链**：先写基础洞（可复现），再写「若结合 X 可达 Y 影响」，把影响范围拉满——但**基础洞必须自己证伪闭**，不能只画链不证基础。

---

## 五、新手三忠告（实战 consensus）

1. **别只盯 XSS/注入**：逻辑漏洞才是冲高额主力，难度低、重复少
2. **长期蹲一个众测平台**：熟悉企业业务风格，越挖越有手感
3. **报告一定要规范**：同样的洞，写得清晰完整更容易定高危、拿高价

---

## 六、一句话

**SRC 出分 = 选对平台（逻辑漏洞泛滥处）+ 抓对功能（状态流转类）+ 改对参数（status/state/前端可控字段）+ 写对报告（根因+可复现+具体影响）。**
