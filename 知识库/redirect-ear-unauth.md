**3xx 截断跳转 = CWE-698 Execution After Redirect (EAR，重定向后继续执行)，是同一个东西的两种叫法。** 本文件两个名字都认，别当两类分开记、分开报。

打开是登录页 / 管理员后台但抓包能看见内容 → 先按 §0 判状态码，再决定走 §1（EAR）还是 §2（路径没盖住）。**判错了整条链都写错，报告会废。**

别和 `open-redirect-test.md` 混：那个是跳外域钓鱼，本文件是**自己家的管理内容/操作在跳转后照样跑出来**，方向相反。

## §0 决定性判定：看状态码，一眼分两类

同样「浏览器跳登录页、抓包能看见后台」，根因可能是两个完全不同的东西。**判定只看第一个响应的状态码**：

| 第一个响应 | 是什么 | 根因 | 报告怎么写 |
|---|---|---|---|
| **`302/301` + `Location: /login` + 响应体有内容** | **3xx 截断跳转 / EAR（CWE-698）** | 鉴权**失败并正确识别了**，但发完重定向**没中断**，后面业务代码照跑 | 重定向后继续执行导致未授权 |
| **`200` + 内容里有 `window.location=` / `<meta http-equiv=refresh>`** | **不是 3xx。是服务端压根没拦 + 前端 JS 跳转** | 鉴权在前端/没配，服务端直接吐内容 | 未授权访问（前端跳转可绕过） |
| **`200` + 纯后台内容，无跳转代码** | 鉴权没覆盖到这个 path | 拦截器 path 匹配不全 | 未授权访问 |

**为什么必须分**：
- 3xx 那类，**业务操作真的执行了**（密码改了、管理员删了），但浏览器跳走了用户看不见 —— 这是「拦了但没拦住」，CWE-698。
- 200 那类，是**根本没进鉴权链**，连拦都没拦。

**怎么抓第一个响应**（浏览器会自动跟随，必须禁掉）：
```
curl -i --noproxy '*' -m 15 -A "Mozilla/5.0" <URL>
# 看第一行状态码 + Location 头 + 响应体
```
Burp 里看 **Response → Raw** 的最顶部状态码，别看 Render（Render 会跟随）。

## §1 3xx 截断跳转 / EAR（CWE-698）

### 原理

`sendRedirect` / `redirect()` **只是写响应头和状态码，不会中断方法执行**。缺 `return` 就继续往下跑：

```java
// 坏：鉴权失败发了 302，但没 return
if (!isLogin()) {
    response.sendRedirect("/login");
}
// 下面照跑
adminService.resetPassword(id);          // ← 真的改了
return new ModelAndView("admin/reset");  // ← 页面照样渲染进响应体
```

```java
// 好
if (!isLogin()) {
    response.sendRedirect("/login");
    return;                              // ← 就差这一行
}
```

各语言同型写法：
- **Java/Spring**：`sendRedirect` / `response.sendRedirect` 后缺 `return`；Filter 里 `chain.doFilter` 后没拦住
- **PHP**：`header('Location: /login');` 后**没有 `exit;` / `die;`**（PHP 里这个坑最多）
- **Node/Express**：`res.redirect('/login')` 后没 `return`
- **Python/Flask/Django**：`return redirect(...)` 一般天然中断，少见；但 `self.redirect()`（Tornado）后不 `return` 会中
- **Go**：`http.Redirect(w, r, "/login", 302)` 后没 `return`
- **ASP.NET**：`Response.Redirect(url)` 不传第二个参数 `true`（`Response.Redirect(url, true)` 才终止）

**PHP 和 Java 是重灾区**，见到这俩技术栈优先查。

### 三档后果（定级差别巨大）

| 档 | 表现 | 定级 |
|---|---|---|
| **① 信息泄露** | 响应体里只有页面：管理员名称、菜单、接口列表、内部路径 | 中危。*有价值的反而在这档*——接口清单是下一步的弹药 |
| **② 未授权读** | 响应体里带**数据**：用户列表、手机号、配置、密钥 | 高危 |
| **③ 未授权写（最狠）** | 请求的是**操作型**接口，跳转后**代码真执行了**：重置密码、删管理员、改配置 | **严重** |

**③ 的判定**：302 的响应体里出现「成功 / 重置成功 / 操作成功 / success」，**并且状态真的变了**（能登录了、人没了）。这才是完整的洞，别只报「能看到页面」就收工。

### 认

- 访问管理路径，浏览器跳登录页，**Burp/curl 不跟随能看到后台内容** → 直接锁定
- 状态码 3xx 但 `Content-Length > 0`（**正常 302 的响应体应该几乎为空**）——这是最快的筛选特征
- 响应体里出现后台才有的字样：管理员昵称、菜单名、`重置密码` `删除管理员` `用户管理`
- **技术栈是 PHP / Java**（老管理后台、自研后台、站点群、OA）

### 打

1. **先拿接口清单**：① 的响应体里翻后台页面的 `href` / `action` / `ajax url`，列全管理端 path
2. **把每个 path 用不跟随跳转的方式各打一遍**，看状态码：
   - `302` + 体有内容 → EAR，进第 3 步
   - `200` → 不是 EAR，是 §2，改走那边
3. **挑操作型接口试③**（重置密码 / 删除 / 改配置），打之前先记下原状态，打完验证状态真变了
4. **有副作用的操作先想清楚**：删管理员、重置密码会动真实数据。能改回就改回，**改不回就停手**，别为了证明继续扩大影响

### 出

- ③：未登录状态下操作型接口返回 302 但业务真的执行（密码被改 / 记录被删），可复现
- ②：302 响应体带真实业务数据

### 假点（别交）

- **只有登录页 HTML**：响应体是「请登录」的空壳，不是后台内容 → 正常重定向
- **响应体有内容但业务没执行**：只有 ① 的信息泄露就报「可重置密码」，是你没验证状态
- **`Content-Length: 0` 的 302**：正常重定向，不是 EAR
- **WAF/网关的拦截页**：`知识库/artifact-intel-guide.md` §3.1 记过，有的拦截页返 200 带「访问禁止」——那是 WAF，不是 EAR
- **SPA catch-all**：前端把所有未知路径 fallback 到首页（返 200 + 首页 HTML）。**这是 200 不是 3xx**，归 §3 不是 §1

## §2 鉴权 path 匹配不全（不是 3xx，但经常和 §1 混）

认：`/admin` 被保护得好好的，`/admin/xxx` 却能直接 200 打开。

常见成因（写代码时的坏习惯）：
- 拦截器配了 `/admin` **精确匹配**，没配 `/admin/**`
- Spring Security `antMatchers("/admin")` 写成不带 `/**`
- 只拦 `/admin/index`，子功能 path 各写各的忘了加
- 大小写 / 结尾斜杠 / `;` 矩阵参数绕过：`/ADMIN`、`/admin/`、`/admin;jsessionid=xxx`、`/admin/.`、`/admin//reset`

打：
1. 拿 §1 第 1 步翻出来的 path 清单，**逐个不登录直接打**
2. 每个都试变体：`/admin/X`、`/ADMIN/X`、`/admin/X/`、`/admin//X`、`/admin;/X`、`/admin/X;.js`
3. 重点是**操作型**接口（重置/删除/导出），不是只读页面

出：不登录 200 打开管理功能，或操作型接口 200 执行成功。

假点：只读页面 200 但没数据；操作型接口 200 但返回「无权限」文案。

## §3 怎么系统性找（别只碰运气撞见）

1. **所有系统路径都别用浏览器看**。浏览器会自动跟随 3xx，永远看不到响应体。统一用 `curl -i` / Burp 不跟随
2. **批量筛 `Content-Length > 0` 的 3xx**：跑一遍后台 path 清单，把所有「状态码 3xx 且响应体非空」的挑出来——这批就是 EAR 候选
3. **优先盯老系统**：PHP / Java 自研后台、站点群、OA、教务、资产系统。新框架（Spring Security 配全的）少见
4. **登录页反查**：任何跳登录页的路径都值得不跟随重打一次，尤其是 `/admin` `/manage` `/system` `/console` 这类
5. **拿到 ① 的接口清单就当资产**：后台页面里的 `href`/`action`/ajax URL 往往比 FOFA 全，直接喂回种子队列

## §4 定级与写报告

- **只报「能看到管理页面」= 中危**，且容易被厂商以「无实际影响」降级。
- **报「未授权重置管理员密码」= 严重**，但**必须证明状态真变了**（改完能登录 / 记录真没了），只截图 302 响应体不够。
- 佐证合并不拆分（见 `src-value-hunting`）：同一个 EAR 根因下的信息泄露 + 未授权读 + 未授权写 **写成一个洞**，别拆成三份交。
- 报告里写清楚根因是「重定向后未 return / 未 exit」，附修复建议（补 `return` / `exit;`），厂商更容易认。

## §5 一句话记住

**浏览器跳走了 ≠ 服务端没执行。** 凡是「跳转」的请求，都要不跟随重看一次响应体和状态变化。
