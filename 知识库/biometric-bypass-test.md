# 生物特征 / 活体检测绕过（实名认证环节）

> **实战案例（双向引用）** → `code-audit-cases.md` §三 + 案例 #19（**绕过人脸识别-2**：某 App 注销的人脸校验点，先本人验证看返回 `{"verified":"true"}`，再拿他人请求把返回包 `verified:false` → `true` 替换放包即通过，定级中危）；§五（`绕过人脸设别.docx` 367KB 未读，与「-2」不同 size 视为另一版本）。**定级参考** `code-audit-cases.md` §七：**人脸绕过多为中危，取决于能否冒用他人身份完成业务**。

**定位**：人脸/活体是实名认证、账号绑定、支付确认的最后一道「人证合一」闸门。SRC 里它的价值在**服务端缺陷**，不在物理冒充。

---

## 一、活体检测机制认知（五大类，知道对手是什么）

| 机制 | 原理 | SRC 视角 |
|---|---|---|
| 动作配合 | 眨眼/转头，验连续性 | 看结果是否只前端校验 |
| 红外光谱 | 血管/温度分布 | 通常硬件级，Web 面难触 |
| 纹理分析 | 皮肤微结构（LBP/深度学习） | 看照片能否过（低安全场景） |
| 3D 结构光 | 光斑形变分析三维 | 硬件级，Web 面难触 |
| 眼动追踪 | 瞳孔/注视轨迹 | 少见，看结果校验 |

> 后四类多为**硬件/算法级**，Web 渗透面小。Web SRC 真正能测的是前两类 + **「活体结果怎么被后端消费」**。

---

## 二、能交的：服务端缺陷（重点）

| 缺陷 | 怎么验 | 判定 |
|---|---|---|
| **活体结果只前端校验** | 改响应包把 `live:false`→`true`（见 `login-bypass-playbook.md` §2） | 改完真通过=洞；刷新回=假点 |
| **活体 token 可伪造/复用/不绑会话** | 抓活体通过后的 token，重放/跨会话用 | 不绑当前会话即可绕过 |
| **人脸与账号绑定可篡改** | 验证时用自己脸过，但回包/请求里 `user_id` 指向别人 → 用自己脸过别人实名（见 `idor-test.md` 改参数） | 绑别人身份=越权实名 |
| **低安全场景照片即过** | 用自己账号、自己照片试，看是否真有活体 | 照片能过=缺陷（用自己测，不冒充他人） |
| **换入口绕过** | 实名/绑卡接口换旧版本/其他入口没挂活体（见 `ratelimit-abuse-test.md` §2.5） | 旧入口没活体 |

**判定红线**：自己账号 + 自己脸/自己照片验证，看机制强度；**绝不冒充他人**、绝不造深度伪造视频过别人实名。

## 三、认知：物理攻击原理（不交、涉红线，只了解）

学术/黑产面：3D 硅胶面具（内置电机）、热成像伪造膜、1200dpi 光泽打印照片、深度伪造视频（DeepFaceLab/FaceSwap）、对抗样本纹理注入、精密模具复制 3D 结构光。

**为什么 SRC 不收/不能做**：
- 这些都需要**冒充特定真实个人**，触犯「非法获取计算机信息系统数据」「侵犯公民个人信息」类法律红线（对齐 `edge-asset-hunting.md` §0）
- 成本高、非 Web 渗透常规手段、且多数平台明确不收
- **认知即可**，只测「自己账号的活体强度」与「服务端校验缺失」

## 五、红线（必看）

- **只用自己账号、自己生物特征**测活体强度，绝不冒充他人
- 不制作/不使用深度伪造、3D 面具等冒充手段
- 发现「活体结果服务端不校验」可交；「我用面具过了某人脸」不交且违法

---

## 六、一句话

**活体在 SRC 里看「服务端有没有真复核活体结果 + 人脸有没有真绑定账号」，不看「你能不能造面具冒充谁」。前者能交，后者违法。**
