## 一、结论速览（TL;DR）

1. **「其他」不是一种漏洞类型，而是"没能归入前 12 类"的倾倒口**——它按**内容体裁**混装，不是按漏洞类型。
2. **762 条里只有约 3~4 成是"可复用手法原料"，其余是教程/科普/电子书/制度文件/图片碎片**。所以**不宜照搬逻辑漏洞/越权那套"全量精读 + 按打法重组"**，成本极高而增量有限。
3. **去重后约 562 份唯一**（762 → Web 397 + EduSRC 147 + App 11 + 小程序 7），重复率约 26%。
4. **真正的增量集中在 4 类**：企业/单位实战测试报告、漏洞类型与代码审计专题、完整攻防链复盘、SRC 赏金方法论——而这四类**大半已被现有手册覆盖**（如 `idor-test.md`/`oauth-jwt-test.md`/`logic-test.md`），需要的是**去重 + 只抽新点**，不是逐份写长文。
5. **发现跨目录重复**：Web「其他」里混入了属于越权/逻辑/EduSRC 目录的文件（`不安全对象调用案例.pdf`、`微信图片_20230303155703.png`（同济 5 图）、`新疆交通1.png`、`第一更/第五更：教育 src 系列`）——说明**该目录还兼作"未归位附件"堆放区**。

> **处置建议（一句话）**：把「其他」**拆成"可挖原料"**与"只归档不精读"两堆，前者按**主题打包**（攻防链 / 代码审计 / 国产 OA / 云原生）增量式补进现有手册；后者（科普系列、电子书、HW 资料、制度、图片）**只做去重清单，不读**。

### 6.2 单点但高密度的技术点
- **`浙江计量科学研究院计量智检系统.docx`**：`/api/actuator/env` 未授权读到 prod 配置（网关路由 / `spring.redis.host` / 数据源），再 `/api/actuator/heapdump` 下 69.3MB 堆转储 → **离线提取明文口令**。→ 补 `middleware-unauth-test.md`（actuator env + heapdump 组合）。
- **`支付原理与案例.docx`**：下单接口"总金额 = 单价 × 数量"且**单价由前端提交**，`price` 7980 → 0.01、数量 ×3，实付 0.03 元下单成功。→ 已在 `logic-test.md` 数值矩阵内，但"**单价前端可控**"这一表述值得作为判定点。
- **`安服仔挖洞记录.pdf`**：从 JS 发现登录成功后跳的 `#/dashboard` **直接拼 URL 绕过登录**（只校验用户名、不校验密码）→ 后台"导出任务列表"的 `filePath` 可读 `/etc/passwd` → FindSomething 提 API + Yakit 对 `/getUser?userid=` 做字典 Fuzz，**参数值字典从"纯数字"换成"中文姓名全拼"**才命中。→ 与 `idor-cases.md` §3.7（客户端鉴权）呼应；**"换语义字典"是新增细节**。
- **`CORS.pdf`**：完整绕过矩阵（`ACAC:true`、ACAO 允许 `null`、字符串包含校验、正则缺锚点、子域劫持、`Vary: Origin` 缺失→缓存投毒）。→ **SRC 不挖 CORS**，仅作资料留存，不进技能包。

### 6.3 教育行业（EduSRC 抽样）
- **`北京中医药大学：正方学生工作管理系统：S2-020+get shell`**：学生账号登录 → `commXszz.do?method=uploadFile` 传 jspx → 读源码取路径 → 构造 `method=...&type=view&a=1&a=1…` **上千个重复参数填充绕参数式 WAF** → 配合 Tomcat `resources.dirContext.aliases=/abcd=/upload/dtjs/` **别名映射**定位马子。

- **`上海交通大学最全资产.xlsx`**：`序号 | 域名 | 长度 | 服务 | 状态 | 指纹 | ip | 标题` 全域子域表。→ **资产测绘前置**的范例；也解释了为何同校漏洞会以多份重复归档。

### 6.4 移动端
- **`渗透测试 记一次安卓渗透流量被加密的解决思路.docx`**（App）：加壳 → 反编译定位 `copyAssets()`，发现把 `nagic{78,71,0,0}` 改写为 `dex\n{100,101,120,10}` **落盘 `.cache` 拿到原生 dex** → IDA 分析 so，`JNI_OnLoad` 未混淆，找到 `getSMValue` → 请求为 `SM2(key) | SM4-ECB(data) | HMAC(SM3)` 三段式 → key 由 `srand(time) + byte_18703A[rand()%62]` 生成 32 字节 → **把 `byte_18703A` 全 patch 成 `0x41('A')`** 使 key 恒定 → `Apply patches to input file` 后替换 so，重启即用固定 key 解密全部流量。**"改密钥表而非改算法"**是绕过随机 key 的最省力路径。
