# edge-asset-hunting

> **实战案例（双向引用）** → `ima-case-corpus.md` §1.3（教务/诊改/数据平台常挂 `:18703`/`:8088` 等高位端口，**从学校主站子页面跳转发现**「数据分析平台」「数据填报」入口）；`other-census.md` §6.3（`上海交通大学最全资产.xlsx` 全域子域表 = 资产测绘前置范例；`学校登录笔记整理.txt`）；`attack-chain-cases.md` §2.1（云上第三方 SaaS 不属 IT 资产但**连的是真实员工**，是优质跳板）。

**偏站 / 老站 / 边缘资产 = 出洞率最高的地方。** 主站防护严、白帽扎堆、常年被扫；边缘资产管理分散、常年不更新、运维不关注。同一套系统，主站打不动，边缘副本往往是裸的。

**教育 / 政府类 SRC 尤其明显**：资产庞杂、历史遗留系统多、安全投入有限、大量系统由学生或外包临时开发。这是新手和高手都该优先砸时间的地方。

**顺序：先找全边缘资产，再按 §3 的薄弱点打。** 找不全就开打 = 拿主站的难度去换边缘的收益，亏。

## §0 红线：这些不做（看到别人写也别学）

网上不少 edusrc 文章会教「社会工程学」，**以下内容全部是红线，本技能永久排除**：

| 文章里常见的写法 | 为什么不碰 |
|---|---|
| 钓鱼邮件（仿冒学校文档、批量发信骗统一认证密码） | 涉嫌诈骗 / 非法获取计算机信息系统数据罪 |
| TG 社工库查师生手机号、邮箱、学号 | 非法获取公民个人信息罪 |
| 购买学生/教师账号 | 非法获取计算机信息系统数据罪 |
| 冒充学生/教师混群骗文件、骗信任 | 诈骗 |
| 拿摄像头画面、学生隐私内容做证明 | 即使有漏洞也不行，证明打码到能定性即可 |

**所有漏洞证明必须满足**：能定性危害的最小证据，**不带真实个人数据**。截图里出现姓名/学号/手机号/证件号一律打码。

**物联网设备（摄像头、打印机、路由器）**：先看 SRC 规则里收不收、范围包不包含。多数教育 SRC 不收摄像头弱口令，别浪费时间；收到了也只报「存在默认口令/未授权」，**不截图画面**。

## §1 边缘资产从哪来（7 类，逐类找）

### A. 环境类子域（最好找，收益稳）

```
old  new  test  dev  staging  beta  demo  uat  sit  pre  gray  alpha  rc
v1  v2  v3  api1  api2  old-api  bak  backup  archive  temp  tmp
2018 2019 2020 2021 2022 2023
```
**重点**：`old.` / `v1.` / 年份子域 —— 这三个命中率最高。老版本往往**鉴权逻辑和新版不同**（新版补了、老版没补）。

### B. 高校 / 政务季节性系统（最容易常年失管）

```
迎新  报到  招生  就业  双选会  招聘  军训  疫苗  核酸  健康打卡  返校
评选  投票  报名  讲座  会议  培训  继教  自考  成教  校友  捐赠
运动会  艺术节  学科评估  专业认证
```
**为什么好打**：用完就没人管，但服务还在跑；开发时赶工期，质量差；数据（学生信息）往往还在里面。

### C. 院系 / 部门独立站（不在主站群）

各学院、实验室、研究中心自己找外包做的，**不在学校主站群的统一防护下**。从主站「院系设置 / 机构导航」页面把所有二级单位链接扒下来，逐个定性。

### D. 未绑域名的 IP 资产（实测最有效）

主站和已确认资产所在的 **同 /24 段**直接扫 80/443 拿 title。见 `recon-fingerprint-cdn-wildcard.md` §2.2 第 10 条。

**实测**：某高校按域名打了 6 轮没结果，扫同段一次挖出 4 个新资产（Harbor、另一个 CAS 实例、网易账户集成平台……），全都是**没绑域名所以 FOFA/CSV 里都没有**的。

### E. 二级目录部署的老系统

主站下的 `/old/` `/2019/` `/bak/` `/test/` `/demo/` `/new/` `/v1/` —— 老系统常整站塞在二级目录里，**和主站同一域名但完全不同的一套代码**，防护也独立。

### F. 老接口 / 版本降级

- 接口带版本号的：`/api/v1/` vs `/api/v2/`，**v1 常不鉴权或鉴权弱**
- 老 APP 的接口：下旧版 APK 或抓老版本包，里面的接口可能还在
- `?version=1` / `?v=1` 类参数降级

### G. 外包商遗留 / 同套系统（供应链打法）

认到某系统是外包商做的 → 查这家外包商还给谁做过 → **同套代码的其他客户站**（用 favicon hash / 版权文字 / 特有 CSS 在 FOFA 反查，见 `recon-fingerprint-cdn-wildcard.md` §1.4）。一个洞通吃一片。

### 补充：已下线但还在线的

- 证书透明度日志（crt.sh）里有、但 DNS 已失效的域名 → 直接访问 IP 或改 hosts 试
- 归档站 / 镜像站 / 已停用但没关的服务

## §2 怎么筛（找到之后排优先级）

**按「老 + 没人管 + 有数据」排序**：

| 筛法 | 怎么做 |
|---|---|
| **按年份** | FOFA / 测绘里看首次收录时间，越早越老。**3 年以上没变过的站优先** |
| **按组件版本** | 认到 Struts2 / Shiro / Fastjson / Weblogic / ThinkPHP / DedeCMS，直接核版本对 Nday |
| **按框架搜** | `domain="xxx.edu.cn" && body="struts"`（把 struts 换成认到的任何框架特征串） |
| **按失管程度** | 页面有过期公告、失效链接、旧年份版权、未清理的测试数据 → 没人维护 |
| **按数据价值** | 含学生/教师/财务/成绩/证件数据 > 纯展示页 |

**优先级**：B（季节性失管）> A（old/v1/年份）> D（没域名 IP）> C（院系独立站）> E（二级目录）> F（老接口）> G（外包同套）

## §3 边缘 / 老站的高频薄弱点（按出洞率排序）

### 1. 弱口令 / 默认口令（老系统最高发）

```
admin/admin  admin/123456  admin/admin123  admin/888888  admin/12345
test/test  admin/1  admin/000000  系统名/系统名  系统名/123456
学号/学号  工号/工号  学号/身份证后6位
```
**纪律**：每系统**只试 3~5 个**（`dig-scope` / `middleware-unauth-test.md` §3 有闸），不要跑字典。中了立刻停手，够定性就够，不要登录进去翻数据。

### 2. 全局未授权访问（老框架鉴权简陋）

老系统常见「登录后才能用」但**接口层没鉴权**。直接不登录打业务接口，看是否返数据。老站比新站高发得多。

打法见 `middleware-unauth-test.md` + `redirect-ear-unauth.md`（后者是 PHP/Java 老后台的 `header` 不 `exit` / `sendRedirect` 不 `return`，**老站重灾区**）。

### 3. 仅前端校验（"学生作品级"后台的典型）

表现：菜单按角色隐藏、按钮置灰、`window.location` 跳转 —— **但接口不校验角色**。
打法：直接构造请求打管理员接口（重置密码 / 删用户 / 导出），不看前端有没有入口。
**这类系统在高校极多**（课程设计、毕设、实验室项目直接上线）。

### 4. 老框架 Nday

认到就核版本：Struts2、Shiro（ rememberMe 默认 key）、Fastjson、Weblogic、Jenkins（`/script` Groovy 控制台）、ThinkPHP、DedeCMS、Discuz、PHPCMS、帝国 CMS。
**用 nuclei 收窄**（`recon-methodology.md` §9），不要全量跑。

**Apache CXF（WebService 框架）**：`/services/` 列服务清单、`?wsdl` 出接口定义。
- **关键认知**：CXF 侧接口**常与前端走不同的鉴权/加密路径** —— 前端登录体加密，**不代表 CXF 也加密**（部署在 CXF 上的接口常被认为"不算敏感"而没加密）。拿到接口定义即可**直接按文档构造 POST**，完全绕开前端与它的加密逻辑。
- **入口来源**：前端 JS 泄露。`*.js.map` 还原源码后抠出 CXF 服务地址与参名（本例参名 `request`、体为 JSON），比翻目录快。
- 完整实战链见 `cmd-injection-cases.md` §五·补（通杀 Edusrc 70 rank）。

### 5. 未授权服务（端口层，老机器常见）

| 服务 | 端口 | 验证 |
|---|---|---|
| Redis | 6379 | `redis-cli -h IP` 后 `info` |
| Memcached | 11211 | `telnet IP 11211` 后 `stats` |
| Elasticsearch | 9200 | `/_cat/indices` `/_nodes` |
| Jenkins | 8080 | `/script` `/manage` 是否未授权 |
| MongoDB | 27017 | 直接连 |
| 打印机 / 路由器 | 80 / 8080 | 直接访问，常无认证 |

工具：fscan / DBscanner / 超级弱口令检测工具。**只在 SRC 范围内扫**。

### 6. ASP / 老 PHP 站：WAF 少

老 `.asp` `.aspx` 站点**加 WAF 的比例明显低**，注入类更容易打。FOFA：`domain="xxx" && (body="asp" || title="...")`，或直接搜 `inurl:asp?id=`。

### 7. 新上线业务（反直觉但重要）

**新功能上线 72 小时内是黄金期**，漏洞率是成熟业务的数倍。盯：SRC 公告、学校信息办公告、新域名证书、新子域。这条和「老站」相反，但同样属于「防护薄弱」。

## §4 进站清单（每个种子过一遍）

```
[ ] A 环境子域：old / v1 / 年份 / test / demo / bak
[ ] B 季节性系统：迎新 招生 就业 打卡 评选 培训 继教 校友
[ ] C 院系独立站：主站「院系设置」页扒全部二级单位链接
[ ] D 同 /24 段扫 title（没域名资产，实测最有效）
[ ] E 主站二级目录：/old/ /bak/ /test/ /v1/
[ ] F 接口版本降级：v2 → v1
[ ] G favicon hash / 版权串反查外包商同套系统
[ ] 筛：按年份老的 + 组件有 Nday 的 + 有数据的，排优先级
[ ] 打：弱口令(限3-5) → 全局未授权 → 仅前端校验 → Nday → 未授权服务
[ ] 全程红线：不社工、不钓鱼、不买号、不截真实个人数据
```

## §5 一句话

**主站是给别人练手的，边缘资产才是出洞的地方。** 找边缘靠的是「把资产找全」，不是靠撞运气——上面 A~G 七类，每类都要过一遍。
