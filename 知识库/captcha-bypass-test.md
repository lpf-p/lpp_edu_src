# 滑块 / 行为验证绕过

**定位**：滑块 / 点选 / 语序 / 无感知这类「行为验证」是登录、注册、短信、风控的闸门。SRC 里它的价值有两类，**先分清再动手**——大多数时候能交的是第一类（机制缺陷），不是第二类（逆向第三方 SDK）。

> **实战案例（双向引用）** → `logic-web-cases.md` **§5**（验证码 8 种姿势：回显 §5.1 / 爆破 §5.2 / 复用 §5.3 / 未绑定 §5.4 / 响应篡改 §5.5 / 客户端校验 §5.6 / 轰炸 §5.7 / 绕过 §5.8）；4 位纯数字验证码全空间爆破的校园实战见 `edusrc-cases.md` §2.4，爆破与限频前提见 `ratelimit-abuse-test.md`。

## 一、能交的：验证机制的「服务端缺陷」（重点）

**不是去逆向极验/易盾/防水墙的加密参数，而是看它实现有没有漏。** 这类才是 SRC 可稳定交的：

| 缺陷 | 怎么验 | 判定 |
|---|---|---|
| **结果只前端校验** | 改响应包 `{"success":false}`→`{"success":true}`（见 `login-bypass-playbook.md` §2） | 改完真放行=洞；刷新回原步=假点 |
| **通过 token 可伪造/复用/不绑会话** | 抓验证通过后的 token，重放/跨会话用 | 不绑定当前会话即可绕过 |
| **后端只校验「调过接口」不校验「结果」** | 直接发带验证标识的请求，不真验证 | 直接带过 |
| **无感知模式形同虚设** | 请求里压根没携带有效验证结果也能过 | 验证被架空 |
| **换入口绕过** | 同一功能换 API 入口/旧版本绕过验证（见 `ratelimit-abuse-test.md` §2.5） | 旧入口没挂验证 |
| **调试开关关验证** | `test=1` / `internal=1` / `debug=true`（见 `logic-test.md` §5.2） | 测试态放行 |

**判定红线**：改完真的放行了 / 能发短信 / 能登录 = 洞成立；只改了显示、刷新又回验证页 = 是后端校验，假点不算。

## 二、认知：第三方 SDK 怎么被绕过（技术原理，SRC 通常不鼓励）

极验 / 易盾 / 防水墙这类商业验证码的绕过通常是**反爬/自动化**范畴，链路由三步组成：

1. **缺口识别**：取背景图 + 滑块图，比对找出缺口 x 坐标（边缘检测 / 模板匹配）
2. **轨迹伪造**：模拟人类加速度曲线（先加速后减速）生成拖动轨迹，绕过轨迹风控
3. **参数加密逆向**：`cb` / `acToken` 等参数是前端 JS 算的，需逆向算法/补环境跑通

**为什么 SRC 一般不鼓励这么做**：
- 多数 SRC 范围**不允许用自动化绕过验证码去打别人业务**（超范围 + 可能构成 DoS）
- 逆向商业 SDK 违反其服务条款，且成本高、易变（版本一升级全废）
- **认知即可**，不要为打 SRC 去逆向第三方验证码

## 三、真正该交的验证码缺陷（与下两篇衔接，不重复）

- 数字/短信验证码：**可爆破 / 可复用 / 前端校验 / 万能码** → `ratelimit-abuse-test.md` §3 + `logic-test.md` §2
- 验证码**轰炸**（无频控） → `ratelimit-abuse-test.md` §4
- 改响应包绕过前端判定 → `login-bypass-playbook.md` §2

本篇只补「滑块/行为验证」这一支：**服务端缺陷能交，客户端逆向超范围不交。**

---

## 四、红线（必看，对齐 `edge-asset-hunting.md` §0）

- 自动化绕过验证码去打别人业务 = 多数 SRC **禁止**（超范围 + DoS 风险）
- 用已确认的验证码**缺陷**（可复用 / 不校验结果）做凭证，而不是逆向 SDK
- 只验证可行性，不批量爆破真实验证码

---

## 五、一句话

**滑块验证在 SRC 里看「服务端有没有真校验结果」，不看「你能不能逆第三方 SDK」。前者能交，后者超范围。**
