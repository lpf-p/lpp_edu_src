# 批量探测与批量报告鉴定纪律（永久）

> 适用：用户授权「集合涉及的全部资产」「按模式库全量过一遍」时走批量；单点目标（某大学授权域名清单）→ 仍走 `dig-scope` 单种子深挖，不批量。
> 本文件是批量验证的**权威规则**。细节只在此一处，别处不重复。

---

## 一、假阳性控制（批量扫描第一铁律）

第一版扫描器用「字符串包含」匹配，产出 24 条命中，**全部假阳性**。根因：没做基线 + 认字符串。修掉后得到 1 条且为既有。教训刻在这里。

### 1.1 必须做基线采样

对每台 host，先打一个**必然不存在**的路径（如 `/__definitely_not_exist_abc123/`），取回 `Content-Length` 和 `Content-Type`，记为**基线**。

- 凡候选命中响应的**长度 / 类型与基线一致** → 一律判假阳性，丢弃。
- 理由：目标自定义 404 页、SPA catch-all 会把一切未知路径渲染成同一个长页面（实测有校站「你迷路了」14 KB 页），字符串匹配必然误中。

**⚠️ 2026-09-18 补 · 泛解析 / 多 CDN 目标还要加「主机级基线」（缺了会整族误判）**

上面的基线是**路径级**的（同一 host 内换路径）。但若 `*.根域` **开了泛解析**，会出现第二类假阳性：**整台主机名根本没被登记，却照样回默认页、甚至回 403**。路径级基线对此**无效**（基线本身就是在同一批主机上取的）。

所以泛解析 / 多 CDN 目标必须取**两条**基线：

| 基线 | 取法 | 判什么 |
|---|---|---|
| **主机级** | 随机生成、绝不可能存在的主机名 `zzz-<16位随机>.<根域>` 的 `GET /` | 这台名字**有没有被边缘登记** |
| **路径级** | `https://<host>/__definitely_not_exist_abc123/` | 这台 host 的**默认错误页**长什么样 |

判定用 **`sha1(body)` 逐字节**比对（不是长度、不是"md5 也行"、更不是关键词）：

| 候选 `sha1(body)` | 结论 |
|---|---|
| ≠ 两条基线 | **异形 ⇒ 确证存在**（哪怕状态码是 404 / 403 / 502） |
| = 主机级基线 | 未登记 / 走默认 vhost |
| = 路径级基线（≠ 主机级基线） | 走默认源站，存在性不确定 |

**配套铁律：**
1. **基线必须与目标同批实时取得** —— 禁止硬编码历史哈希、禁止跨天取、禁止从旧报告抄。
2. **禁止把判据退化为关键词匹配** —— 实测用 `sf-reset` / `Exception` 判"是不是 Symfony"必然误中（该串**本就在 Symfony 默认 404 模板自身里**），见 §1.2。
3. **禁止用 IP 判 CDN 归属** —— CDN 多节点，同一条 CNAME 两次解析会得到不同 IP。

> 完整判据（**双轨四象限** / CNAME 辅助判据 / 泛解析下**失效**的旧判据）见 `rules/asset-existence-and-coverage.md`。

### 1.2 只认结构性证据，不认字符串包含

| 探测项 | 字符串匹配的坑 | 结构性证据（**必须全部满足**） |
|--------|----------------|-------------------------------|
| Nacos | `/nacos/` 命中目标自定义 404 页（页里含 "nacos" 字样） | 返回 Nacos 登录页 HTML 结构，且响应长度 ≠ 基线 |
| Swagger | SPA 404 兜底页的 JS bundle 含 `swagger` 字符串 | 响应是 JSON 且含 `"swagger":"<num>"` 或 `"openapi":"<num>"` 键 |
| GitLab | — | JSON 同时含 `"version":"<数字>"` 与 `"revision"` |
| 备份 zip | 匹配 `PK` 魔数误中 base64 资源名 `pkRMqP_xxx.png` | `Content-Type: application/zip`（不是 image/png），且首字节 `PK\x03\x04` |
| Druid | elog 错误页含 `druid" not defined in elogd.cfg` | 真正 Druid 监控页（`/druid/index.html` 含 stat 等） |
| Actuator | — | 特定端点返回结构化 JSON（如 `{"status":"UP"}`），非通用 404 |

**⚠️ 通用陷阱：裸单词匹配（2026-09-16 实测踩坑，写自己工具时又犯了一次）**

工具里用**大小写不敏感的子串匹配**去认产品名，几乎必然假阳性。实测踩到的：

| 裸单词 | 实际误中 |
|---|---|
| `indico` | **`indicator`** / `indicating` / `indicative` —— 任何含 "indico" 的英文词 |
| `elog` | 任意含 `elog` 的词（含 `elogd.cfg`） |
| `WordPress` | 前端注释 / 无关文案里的字样 |
| `gitlab` / `jenkins` | JS bundle 里的字符串常量 |

**修法**：① 默认**大小写敏感**；② 优先用**结构性串**（`/indico/`、`ELOG - `、`wp-content`、`/assets/gitlab`）；③ 只在标识本身足够独特时才用裸单词（如 `ecology_JSessionid`、`mattermost`）。

### 1.3 单请求范式

每个候选 path 一次 curl 同时取头 + 体 + 状态码，避免每条 4 次请求拖慢（实测 4 次/条跑 261 主机要 23 分钟且 incomplete）：

```bash
curl -s -D "$T/h" -o "$T/b" -w "%{http_code}" "$URL"
```

流程：取基线长度 → 过滤掉长度 = 基线的 → 对通过者做 1.2 结构性判据 → 才记为命中。

## 二、批量报告鉴定（别人给的「N 份报告 / zip 全集」）

收到「漏洞报告全集 N 份」「202 份打包」类压缩包 → **先鉴定可交性，不要逐份复现浪费时间**。

### 2.1 去重量化

- 统计每份是否含同一探针路径 / 同一指纹。泛微 e-cology：`/api/ec/dev/app/test` + `getOSinfo` + `wev8`/`ec_id` 同现。
- 结论模板：`N 份 = 1 个漏洞 × M 主机`（实测：202 份 = 1 漏洞 × 124 hosts）。

### 2.2 模板化批量生成识别

- 多份报告同一套话术、同一张图、同一定级 → 套模板机刷产物。
- 标错厂商的（实测 34 份写「万户 OA」实为泛微）→ 证明是批量生成，可信度低。

### 2.3 判定口径

- 判为「同一洞 × N 主机」→ 对你自己只有 **1 条**可交，且先查平台是否已收录该洞。
- 仅版本指纹（只给版本号无利用）/ 独立无关联低危 → 不交。

## 三、根本结论

批量扫完若「0 新增」，是**正常结果**，说明这条路对该资产池已走到头——不要为凑数放宽判据。换方向（业务逻辑 / 越权 / 小程序公众号）比重复扫更有产出。实测 114 校 / 261 主机 / 16 类模式 ≈ 4200 次 GET，严格通过 1 条且为既有发现，即此结论。

## 四、批量也吃「反早闭」（2026-09-18 补）

批量最容易出的错其实不是假阳性（那有 §一 三条铁律挡着），是**假阴性**：一批 261 台，命中 1 条就收工，**剩下 260 台到底排除干净没有，没人说得清**。

1. **每类模式的筛除结论也要能答「还没排除什么」** —— 例：Nacos 只试了 `/nacos/` 一个 path，其余变体（大小写 / 后缀 / 版本路径）试没试？答不出就别写「已排除」。
2. **一旦从批量筛进入逐项验证**（盯住某台深挖），判定状态与 `unruled_out` 认 `rules/verdict-states.md`，不再走本文件。
3. **批量判死 ≠ 单点判死。**「整批 0 新增」是**批量筛**的结论（可以据此收工换方向），**不等于**"这些站安全"。别把批量结论当站点结论用。

**一句话：** §一 管「别把假的当成真的」（假阳性）；`verdict-states` 管「别把真的漏了、还当测完了」（假阴性）。批量两个都要，少一个都不叫测完。
