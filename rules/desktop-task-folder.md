# 桌面任务文件夹（永久强制 · 任务根格式）

> 用户强制（2026-08-04 再确认；**2026-08-04 再加硬：独立 `js/` + 资产只放公网 URL**）：  
> 叫我做任务时，**按「{目标}_SRC挖洞」那种格式**在桌面建任务根目录；分夹清楚、条例清晰。  
> **禁止**把报告/脚本/资产/js 直接堆桌面根；**禁止**只丢一个扁平 `xxx_dig` 就把报告塞 dig 里凑合。

---

## 1. 标准目录格式（永久模板）

桌面任务根命名：`{目标/主题}_SRC挖洞` 或同等清晰中文名。

**开新任务时必须一起建齐：**

```
Desktop\{任务名}_SRC挖洞\
  README.md          ← 任务说明、目录结构、进度、续跑命令
  资产\              ← 挖掘途中发现的「公网可挖 URL 资产」（域名/URL 清单）
  js\                ← 从站点提取/下载的 JS 源文件（分析用）
  报告\              ← 正式报告
  {短名}_dig\        ← 脚本、queue、dig-state.json、findings、日志、临时探测
```

**对照范例（必须对齐）：** `Desktop\{目标}_SRC挖洞\`

| 子目录 | 放什么 | 不放什么 |
|--------|--------|----------|
| `资产/` | 公网可挖 URL/域名清单（挖掘途中发现并沉淀的目标资产：url 列表、子域、接口入口 URL、FOFA 导出里的可打面等）；**自由跳还必须有 `种子队列.md`**（业务名/品牌/SRC 域/全资域 + pending/doing/done，见 dig-scope §1.4；数量无上限）；**锁面还必须有 `资产账本.md`**（逐台存在性判定 + 覆盖率，见 `asset-existence-and-coverage` §6） | **禁止**塞提取的 `.js`；禁止报告、跑扫脚本 |
| `js/` | 从目标站点**提取/下载**的 JS 文件（LinkFinder/手动抓包/批量下的前端包），供逆向接口用 | 禁止正式报告；禁止把「URL 资产清单」塞这里 |
| `报告/` | 正式报告 `.md`（文件名=漏洞标题） | 脚本、state、半截日志、JS 原文 |
| `{名}_dig/` | dig 脚本、queue、`dig-state.json`、findings、验证小脚本、日志、临时探测；**开新任务必须有 `线程必读.md`（迭代闸，见 `hunt-iter`）** 与 **`dig-state.json`（断点续跑，见 §1.2）** | 最终交付报告；**定稿的提取 JS 应落到 `js/`，不要只堆 dig 里当资产** |
| `README.md` | 结构说明、进度表、续跑命令、收录纪律；**必须有迭代闸一行**（见 `hunt-iter.md`） | — |

### 1.1 资产 vs js（强制分清）

| 内容 | 正确路径 |
|------|----------|
| 公网可挖的 URL / 域名 / 入口清单（挖途中发现的可继续打的面） | `资产/` |
| 从页面/CDN 抽下来的 `.js` 源文件 | `js/` |
| 临时下载、半截、仅用于一次探测的 JS/HTML 缓存 | 可先在 `{名}_dig/`；**有分析价值的正式提取件 → 移入 `js/`** |

**禁止（用户点名）：** 再把提取的 JS 丢进 `资产/`。

### 1.2 `dig-state.json`（断点续跑 · 2026-09-18 补）

> **为什么要有：** 挖站是长任务，跨会话、跨天、被压缩之后，**"停在哪、下一步测什么" 只在对话里**——对话一断就得靠人复述。
> `线程必读.md` 是**给人看的**迭代闸；`dig-state.json` 是**给下一轮的你读的**进度闸。两份并存，不是替代。

文件：`{任务根}/{名}_dig/dig-state.json`（一个任务一份，**不按 host 拆**）。

```json
{
  "task": "{任务名}",
  "mode": "锁面 | 自由跳",
  "stage": "存在性 | 指纹 | 清单 | 矩阵 | 报告 | 自查",
  "doing_host": "当前正在挖的 host（没有写 null）",
  "seed_pending": 0,
  "tested": [
    {
      "host": "webvpn.**.edu.cn",
      "surface": "/xxx/login",
      "threat": "认证与会话·验证码可复用",
      "status": "not_vulnerable",
      "unruled_out": "未排除：类型混淆（int/str 传参）、并发复用",
      "coverage_note": "输入面：username/password/captcha 三个入参都测了；行为面：本功能点仅 1 个接口；深度面：只试了复用与省略。"
    }
  ],
  "next": ["下一步要打的具体入口（一到三条，写 URL 级）"]
}
```

**字段（只用这些，别加）**

| 字段 | 作用 |
|------|------|
| `stage` | **断点主字段**：下轮开工先读它，从这一步接着走 |
| `doing_host` | 半截站靠它接上，避免重新开矩阵 |
| `seed_pending` | 自由跳的换种判据；与 `资产/种子队列.md` 的 pending 数一致 |
| `tested[].status` / `unruled_out` | 状态词只认 `verdict-states.md` 的五个；`not_vulnerable` 必须带 `unruled_out` |
| `tested[].coverage_note` | §4.1.4 的覆盖三问答案（输入面 / 行为面 / 深度面），**一句话一句**，不要表格 |
| `next` | 只写**入口级**，一到三条；写多了等于没写 |

**硬规矩：**

1. **每轮收尾写回**（换 host、换种子、落报告、收工前各写一次）。
2. **跨会话开工先读它**，再从 `stage` 与 `next` 接着走；**禁止**读完只记得用户原词。
3. **⛔ 禁止写入任何凭据实值** —— Cookie / token / 密码 / 密钥一律不进本文件，只写 host、路径、参数名、状态词。凭据只在当轮内存里用（与 `vuln-report-format`「会话 Cookie 实值绝不进材料」同源）。
4. **本文件不是报告也不是短表**：不写危害、不定级、不进 `报告/`；写不写报告只认 `vuln-report-format`，进不进短表只认 `hunt-iter`。
5. 早期任务没这份文件不追责；**开新任务必须建**（建一份带 `stage` 与空 `tested` 的骨架即可）。

## 2. 硬规则

1. **一任务一根目录**，起手就建，再开始产出。
2. **四类分夹 + dig**：`资产/` + `js/` + `报告/` + `{名}_dig/` — **条例清晰，不混放**。
3. 报告路径固定：`{任务根}/报告/`；脚本里 `REPORT_DIR` 必须指向这里。
4. 提取 JS 路径固定：`{任务根}/js/`；下载/提取脚本默认输出到这里。
5. URL 资产路径固定：`{任务根}/资产/`；只写公网可挖 URL/域名类清单，不写 JS 文件。
6. 续跑、增量、Pass2/3/4 → **仍进同一任务根**，不另开桌面散文件。
7. 桌面根 **禁止** 再落报告 `.md`、queue、state、零散 py/js。
8. 用户已指定路径时以用户为准；未指定 → 本格式。
9. **开新任务必须带迭代闸：** 起手建 `{名}_dig/线程必读.md`，写「迭代见 `hunt-iter.md`」。`README.md`、自由跳的 `资产/种子队列.md` 顶部钉同一句。拉子线程交付必须含迭代。条文只在 `hunt-iter.md`。
10. **开新任务必须建 `dig-state.json`**（骨架即可：`task` / `mode` / `stage` / `doing_host` / `seed_pending` / `tested: []` / `next`）；**每轮收尾写回**，跨会话开工先读。⛔ 凭据实值绝不进本文件。条文只在 §1.2。

## 3. 用户说「清理」时（操作）

口径只认 `vuln-report-format.md`「清理」那一行。本文件只写怎么删、删哪、浏览器别动。

判定「有报告」：`{任务根}/报告/` 存在且至少 1 个正式报告 `.md`。夹不存在或空 = 无报告。

### 3.1 无报告 → 整根全清

| 动作 | 说明 |
|------|------|
| **删除整个任务根目录** | `Desktop\{任务}_SRC挖洞\` 整棵移除 |
| 含其内一切 | `资产/`、`js/`、`{名}_dig/`、`README.md`、过程垃圾等**一并删**，不单独保留资产 |

适用：无洞任务、只跑了 dig/资产/js 没交报告、空 `报告/` 夹。

### 3.2 有报告 → 只留「资产 + 报告」

| 保留（禁止删） | 删除（可清） |
|----------------|--------------|
| `{任务根}/报告/` 及夹内全部文件 | `{名}_dig/` 整夹 |
| `{任务根}/资产/` 及夹内全部文件 | `js/` 整夹 |
| 任务根目录本身（外壳留下） | `README.md`、其它散落脚本/日志/临时文件 |
| | 桌面根误落的本任务相关垃圾 |

有报告时：**禁止**删 `报告/`、`资产/`；**禁止**把报告/资产挪没再整根删掉任务根。  
清理后形态：

```
Desktop\{任务}_SRC挖洞\
  资产\     ← 保留
  报告\     ← 保留
```

（无 `js/`、无 `*_dig/`、无 README 亦可。）

### 3.3 范围

1. 用户说「清理」且**点名任务** → 只处理该任务根。  
2. 用户说「清理」且指**所有任务文件夹 / 理一遍规则落地** → 桌面上全部 `*_SRC挖洞`（及同等任务根）按 §3.1 / §3.2 逐个处理。  
3. **不是**任务文件夹的目录（工具、SRC文档资料夹、普通软件安装包等）**不要**当任务根误删。  
4. 会话 **桌面** `.playwright-mcp` 下本轮 snapshot/console **文件**可清（仅该目录内临时截图/日志）。

### 3.3.1 浏览器账号密码与配置 — 永久禁止清（2026-08-04 用户点名）

> 用户明确：**以后清理不要把浏览器保存的账号密码清理了。**

清理时 **一律禁止** 触碰、删除、重置、清空下列对象（即使用户只说「清理」）：

| 禁止对象 | 说明 |
|----------|------|
| 浏览器已保存的账号 / 密码 / 自动填充 | Chrome/Edge 密码库、Login Data、Autofill |
| 浏览器用户配置目录 | `User Data`、`Default`、Profile、`Login Data`、`Web Data`、Cookies 库整夹 |
| CDP/9222 所连真实浏览器的 profile | 不得 `ClearBrowserCookies` 整库、不得关「保存密码」、不得 wipe 凭据 |
| Playwright 持久化上下文里的凭据存储 | 不得清 storage state 中用户依赖的登录保存（任务 dig 内临时 cookie 文件可随 dig 删） |

**允许清的浏览器相关垃圾（仅限）：**

- 桌面 `Desktop\.playwright-mcp\` 下 **snapshot / console 临时文件**（页面快照、控制台导出）  
- 任务 `{名}_dig/` 内过程 cookie 文本、探测缓存（**不是**浏览器密码库）

**禁止** 为「清理」执行：关闭浏览器用户配置、删除 Profile、`Clear-Site-Data` 全站、重置浏览器、清「密码和表单」、对 9222 浏览器做全局 storage clear。

### 3.4 执行顺序

1. 列出待处理任务根（点名 or 桌面 `*_SRC挖洞` 等）  
2. 每个任务根检查 `报告/` 是否**有文件**  
3. **无报告** → `Remove-Item` 整棵任务根  
4. **有报告** → 只删 dig / js / README / 其它；**锁定保留** `报告/` + `资产/`  
5. 若有报告但无 `资产/` 夹 → 可保留空 `资产/` 或不建；**绝不动 `报告/`**  
6. 浏览器：只可清桌面 `.playwright-mcp` 临时 snapshot/console；**绝不碰密码库/Profile**

### 3.5 自检（清理前）

- [ ] 是否先数过 `报告/` 里有没有文件？  
- [ ] 无报告时是否整根删（含资产/js/dig）？  
- [ ] 有报告时是否只留了 `资产/` + `报告/`，没有误删报告？  
- [ ] 是否误把非任务目录（如 `SRC文档` 资料夹）当任务根删了？  
- [ ] **是否会误清浏览器保存的账号密码 / Profile / Login Data？禁止则继续。**

## 4. 自检（写文件 / 交报告 / 开新任务前）

- [ ] 是否已有 `Desktop\{任务}_SRC挖洞\`（或用户指定等价结构）？  
- [ ] 是否具备 `资产/` `js/` `报告/` `{名}_dig/` `README.md`？  
- [ ] 提取的 JS 是否只在 `js/`（**不在** `资产/`）？  
- [ ] `资产/` 是否只是公网可挖 URL/域名类清单（含 `种子队列.md` / 锁面的 `资产账本.md`）？  
- [ ] 锁面是否有 `资产账本.md`，且「判定」列无空缺？（`asset-existence-and-coverage` §6）  
- [ ] 报告是否只写在 `报告/`？  
- [ ] dig 状态与脚本是否只在 `{名}_dig/`？  
- [ ] **`dig-state.json` 是否建了、且本轮的 `stage` / `next` 已写回？里面**没有**任何 Cookie / token / 密码实值？**  
- [ ] 有没有东西误落在桌面根？有则 **移入对应子夹**（不是删掉糊弄）

---

**一句话：** 开新任务 = `README + 资产(公网URL) + js(提取JS) + 报告 + *_dig(线程必读 + dig-state.json)`；**JS 绝不进资产**；**凭据绝不进 dig-state**。清理口径只认 `vuln-report-format`。
