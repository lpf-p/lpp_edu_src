# 判定状态词与反早闭（永久）

> **2026-09-18 新增。** 对标一个外部的授权渗透工作台 skill 后吸收：把「一个威胁项到底测到什么程度」**定成固定词表**，堵掉报告里「疑似 / 可能 / 应该是越权」这种没结论的写法。
> **本文件是判定状态与反早闭的唯一来源。** 报告怎么写仍只认 `vuln-report-format.md`；**资产的**存在性判定认 `asset-existence-and-coverage.md`（对象不同——那份判**资产**，本份判**漏洞 / 威胁项**）。

---

## 一、三层确认门（一个威胁项过三道才算 `confirmed`）

```
第一层 可达性     Access           能不能调到 / 触发到这个点？
第二层 脆弱性     Vulnerability    调到之后，有没有真危害？
第三层 可利用性   Exploitability   危害是不是真能落地？
```

| 层 | 判什么 | 是门票还是证据 |
|----|--------|----------------|
| 可达性 | 返回 200 / 业务 `code=0` / 报错差异 | **只是门票**。单独过这层 = 未验证 |
| 脆弱性 | 返回的是不是「不该给当前请求者看 / 做」的东西；操作有没有实际损失 | **核心判定层** |
| 可利用性 | 越权读：响应里**真有他人的**私有数据；越权写：**二次查询确认值真变了**；密钥：**真能解密 / 签名** | 全过才 `confirmed` |

**⛔ 只过第一层就写报告 = 假阳性。** 四句口诀（与 `vuln-report-format.md`「接口 200 有 JSON → 不写」同源）：

```
接口能调通 ≠ 有漏洞
返回 200   ≠ 确认漏洞
不带认证   ≠ 越权
有返回数据 ≠ 信息泄露
```

## 二、状态词表（只有这五个 · 禁止自造）

| 状态 | 含义 | 能不能进报告正文 |
|------|------|------------------|
| `confirmed` | 三层全过，证据链完整（请求 + 响应 + 业务影响验证） | ✅ 按 `format` 落 `报告/` |
| `suspicious` | 响应异常，但业务影响未验证 | ❌ 进盲区清单；补证到位才升 |
| `not_vulnerable` | 试过多个合理变体均无效，**且已填 `unruled_out`** | ❌ 进盲区清单 |
| `blocked` | 环境限制测不了（人机 / 断网 / 无权限 / WAF 死挡） | ❌ 进盲区清单 |
| `needs` | 缺一个前置条件才能往下（有效对象 id / 第二个号 / 有效订单号） | ❌ 进盲区清单，写清缺什么 |

**硬规矩：**

1. **禁止自然语言状态。**「疑似」「可能」「应该是」「大概」「后续再看」→ 一律换成上面五个词之一。
2. **只有 `confirmed` 能进正式报告**的中危及以上；其余四个进报告的**盲区清单**（§四）。
3. **`suspicious` 不是终点** —— 要么补测到 `confirmed`，要么按 §三降级成 `not_vulnerable` / `needs`。挂着 `suspicious` 不收工。

## 三、反早闭：`not_vulnerable` 必须附 `unruled_out`（硬 · 本文件最要紧一条）

> **病：** 试了一种姿势没打中，就判「这个点安全」，然后整场再也没回来看。
> **这是假阴性** —— 不是「把假的当真的报」（假阳性，那归 `batch-verify-discipline`），是「**把真的漏掉了，还以为测完了**」。两半缺一不可。
> 实测最常见的漏：验证码只试了「省略」没试「复用 / 类型混淆」；注入只试了报错没试布尔 / 时间盲；弱口令只在一个登录口试了就类推到其余口；用户枚举只看了一处报文没看时序差。

**规矩：标 `not_vulnerable` 之前，先列「针对这个机制 / 这个输入，我还没排除什么」——逐条要么当场补测，要么写明为何可排除。**

```json
{
  "threat": "资源归属·订单详情换 id",
  "status": "not_vulnerable",
  "unruled_out": "未排除：① 换 METHOD（GET→POST/DELETE）；② /order/export 同族接口未试；③ 邻号与 0/-1 未试。"
}
```

**照抄即用的自问清单（别自己发明）：**

- [ ] 验证码：排除「省略 / 空 / 复用 / 类型混淆」了吗？
- [ ] 短信码 / OTP：排除「爆破 / 类型混淆 / 并发复用」了吗？
- [ ] 注入：报错排除了，**布尔 / 时间盲 / 带外**排除了吗？
- [ ] 用户枚举：只看了一处报文？**时序差 / 注册与找回的差异响应**看了吗？
- [ ] 弱口令：每个登录口（用户 / 管理 / 商户）**分别**测了，还是拿一个的结论类推的？
- [ ] 越权：换了 id，**换 METHOD / 换同族路径**（`/api/x` ↔ `/api/x/export`）试了吗？
- [ ] 上传 / 模板：只试了一个后缀 / 一个引擎？其他后缀、其他引擎写进 `unruled_out` 了吗？

**⚠️ 不确定 ≠ `not_vulnerable`。** 不确定就归 `suspicious` 或 `needs`。**禁止拿 `not_vulnerable` 装「我已经查过了」。**

### 覆盖三问（每个功能点收口前答一遍，写进 `dig-state.json` 的 `coverage_note`）

| 面 | 问 |
|----|----|
| **输入面** | 本功能点的**每个**外部可控输入（参数 / 字段 / 文件 / 路径 / 请求头 / URL），都「要么测了、要么写明为何不测」了吗？哪个是含糊过去的？ |
| **行为面** | 本功能点的**每个**接口、**每个**会改状态的动作、**每个**能并发的点、**每个**角色组合，都覆盖了吗？ |
| **深度面** | 我判 `not_vulnerable` 的，是真穷尽了，还是一种姿势就收？（这些写进 `unruled_out`，不是写「已测」） |

三问**不点名任何漏洞类型** —— 所以什么洞型都会自动落进某一问，逼你想「这个输入还可能是什么」，而不是照着漏洞清单对号入座。

## 四、盲区去哪（单洞报告不附 · 客户交付才成块）

**单洞 SRC 提交不附盲区清单** —— 平台只收这一个洞的证明，附了反而稀释。没结论的（`suspicious` / `blocked` / `needs`）写进 `{名}_dig/dig-state.json`，**不塞进 `报告/`**（口径见 `vuln-report-format.md` §二「盲区去哪」）。

**客户交付 / 内部复盘**要另出一块盲区清单，只用三个词：

```
BLOCKED   环境限制测不了，写清卡在哪（人机 / 断网 / 无权限 / WAF 死挡）
NEEDS     缺一个前置条件才能往下，写清缺什么（有效对象 id / 第二个号 / 有效订单）
N/A       这个面本功能点确实没入口，写清为什么没有
```

**禁止措辞**（与 `vuln-report-format` §三 忽略规则 #6「描述不清、无法复现」同源）：

| 禁用 | 应写成 |
|------|--------|
| 部分覆盖 / 基本完成 | `BLOCKED` / `NEEDS` / `N/A` 三选一 |
| 待后续验证 | `NEEDS` + 缺什么 |
| 疑似 / 可能 / 应该是 | `suspicious` + 未验证的具体点；或补测 |
| 未授权访问漏洞 | 具体是越权读 / 越权写 / 信息泄露 + 字段（见 `format` §三 3.1） |
| 可导致资金损失 | 除非已验证真实资金 / 积分变动，否则不写 |

## 五、五个判据文件别混（对象不同）

| 文件 | 判的对象 | 一句话 |
|------|----------|--------|
| **本文件** | **单个漏洞 / 威胁项**测到什么程度 | 三层门 + 五个状态词 + `unruled_out` |
| `asset-existence-and-coverage.md` | **资产**存不存在 | 双轨四象限 + 覆盖率账本 |
| `batch-verify-discipline.md` | **批量命中**是真命中还是假阳性 | 基线采样 + 只认结构性证据 |
| `hunt-iter.md` | **手法**进不进短表 | 门槛 + 三问 |
| `vuln-report-format.md` | **写不写 / 怎么写 / 落哪** | 报告唯一来源（本文件不改版式） |

**两半合起来才叫「不误报也不算漏」：**

- 假的当成真的 → `batch-verify-discipline`（假阳性）
- 真的没打中、还当测完了 → **本文件 `unruled_out`**（假阴性）

---

**一句话：** 一个点测完只有五种说法 —— `confirmed` / `suspicious` / `not_vulnerable` / `blocked` / `needs`；**只有 `confirmed` 进报告正文**，其余进盲区清单；**标 `not_vulnerable` 必须先写 `unruled_out`**（还没排除什么），**不确定就别说安全**。
