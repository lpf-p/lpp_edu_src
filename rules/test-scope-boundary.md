# 各类漏洞的最大测试范围（停止线）

> 用途：动手前查这张表，明确「测到哪一步算到底」。
> **核心原则：证明「存在」即停，不追求「最大化利用」。** 多做的部分既不会加分，还会把自己从「白帽」做成「攻击者」。
> 依据：`vuln-report-format.md` §3.3（EDUSRC 15 条忽略规则）、`SKILL.md` 安全红线、`security-research-context.md`。

## 零、通用停止线（所有类型适用，先过这七条）

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | **只读优先**：能用 GET/列表差分证明的，绝不用写操作 | 越界 |
| 2 | **单请求、低频**（1-2 线程、串行）。禁止并发压测、禁止 DoS | 平台忽略 + 法律风险 |
| 3 | **禁止留存真实敏感数据**：身份证、手机号、姓名、成绩、银行卡、密码 —— 看到即记录「存在该类数据」，**不下载、不复制、不写进报告原文** | 违法 |
| 4 | **禁止破坏性操作**：删改数据、改配置、拖库、留后门、装持久化 | 违法 |
| 5 | **禁止登出/注销**：拿到登录态后全程不得调 `/logout`、`/revoke`，也不测「退出后会话还有效」 | 把用户号搞死 |
| 6 | **需要第二个账号时用自己的**。拿不到两个账号就写「待验证步骤」，**不编造越权结论** | 报告被驳「无法证明是越权」 |
| 7 | **范围只限授权目标**：不碰第三方供应商、C 段、旁站、非在册域名 | 出范围 |

## 一、按漏洞类型的最大测试范围

### 1. 水平越权（IDOR）

- **最大范围**：两个自有账号 A→B 交叉，**读到 B 的一条数据**（用自己的数据即可，不必读他人真实数据）。
- **停止线**：证明「换 ID 能读到不属于当前账号的数据」。截图 + 两个账号的请求对照。
- **越界**：改/删 B 的存量数据；批量遍历 ID 拉全表；留存读到的他人信息。
- **技巧**：优先找「自己的第二个账号」，比读他人数据安全得多。

### 2. 垂直越权（BFLA）

- **最大范围**：普通账号调用管理接口，**返回数据（哪怕是一条）即停**。
- **停止线**：证明「低权限可访问高权限接口」。
- **越界**：真创建管理员账号；改别人角色；删除真实数据。**创建后必须删掉自己刚建的那条**。
- ⚠️ 禁止把「只验证只读」理解成「写 IDOR 不用测」——写越权仍要测，只是顺序是「先添加 → 再删自己那条」。

### 3. 未授权访问（接口 / 后台 / 中间件）

- **最大范围**：匿名访问，**读到单条/首页数据即停**。中间件（Nacos/Actuator/Swagger/ES）看到配置或接口列表即停。
- **停止线**：证明「无需认证即可读」。
- **越界**：翻页到底、下载全量、连数据库导出。
- ⚠️ **只开 health/info 的 Actuator、只渲染枚举值表的未授权页面 → EDUSRC 判「无意义信息泄露」忽略**，只能并入主链当佐证。

### 4. SQL 注入

- **最大范围**：`version()` / `@@version` / 库名 / 当前用户，或盲注取版本号。**读 1~3 行非敏感数据足矣**。
- **停止线**：证明可执行 SQL、能读库。
- **越界**：拖用户表、读身份证/密码、`xp_cmdshell`、写文件 getshell。
- ⚠️ 若读到了身份证/密码，报告里**只写「可读取该表 N 条含敏感字段记录」并打码**，不贴明文。

### 5. 命令注入 / RCE

- **最大范围**：`id` / `whoami` 回显，或 DNSLog / HTTP 外带**一次**。
- **停止线**：证明命令可执行。
- **越界**：反弹 shell、提权、横向、留后门、装持久化。
- ⚠️ 反序列化同理：DNSLog 探测即停，不真 getshell。

### 6. 文件上传

- **最大范围**：传一个**内容无害的探针文件**（如输出 `phpinfo()` 或 `md5(1)` 的最小文件）并证明被解析执行。
- **停止线**：证明可上传 + 可解析（或证明绕过黑名单）。
- **越界**：传大马、连马、提权、留后门。
- 无法证明解析时：**停在「上传成功 + 路径可访问」**，如实写「未验证解析」。

### 7. SSRF

- **最大范围**：读云元数据（如 `169.254.169.254` 的基本信息）、或 DNSLog 外带、或探测内网端口**证明可达**。
- **停止线**：证明服务端可发起外部/内网请求。
- **越界**：打内网 Redis 写计划任务、打 FastCGI、横向移动、探测整个内网段。
- ⚠️ WebVPN 类入口**只验证不挖**——证明内网可达即停手。

### 8. XSS

- **最大范围**：**自己的账号**弹 `alert(document.domain)`（反射/存储/DOM 同）。
- **停止线**：弹窗截图 + 完整 PoC。
- **越界**：打他人 cookie、构造钓鱼页、窃取真实用户会话。
- ⚠️ **Self-XSS 平台直接忽略**（规则 9）；盲打 XSS 要有回连证明才交。

### 9. 支付 / 订单 / 金额逻辑

- **最大范围**：下单流程**走到提交前**，证明金额/数量可篡改（改成 0.01 或负数）。
- **停止线**：证明服务端接受篡改后的金额。
- **越界**：**真实支付、真实退款、任何造成实际资损的操作**。
- ⚠️ 这是最容易出事的一类，**宁可只报「参数可篡改」也不要真下单**。

### 10. 优惠券 / 积分 / 限购

- **最大范围**：证明可重复领取 / 可绕过限购，**领到即停**（不使用、不核销）。
- **停止线**：证明逻辑缺陷。
- **越界**：真使用、真薅、批量领取。

### 11. 验证码 / 短信 / 邮件

- **最大范围**：用**自己的 1~2 个手机号**，测 3~5 次，证明「可爆破 / 可无限发送 / 验证码在响应包回显」。
- **停止线**：证明存在缺陷。
- **越界**：短信轰炸他人、大量调用、用他人号码测试。
- ⚠️ 看到验证码在响应包回显 = 直接中危以上，**截图即停**。

### 12. 密码重置 / 账号接管（ATO）

- **最大范围**：**只在自有账号上跑完整流程**。能改自己密码即证明链路成立。
- **停止线**：证明「身份校验可绕过」。
- **越界**：接管他人账号、改他人密码。**若必须验证他人账号才能证明，宁可报「疑似」并写明未完成接管**。
- 定级纪律：闭环未打通（改密页有服务端会话校验）→ **必须如实写「未完成账号接管」**，宁可中危不虚报严重。

### 13. 认证绕过（登录 / 统一认证 / CAS / OAuth / JWT）

- **最大范围**：自有账号 + 修改请求/响应验证，**登录进自己账号即停**。
- **停止线**：证明可绕过某道校验。
- **越界**：登录他人账号、遍历学号+初始口令批量试。
- ⚠️ 「需管理员登录才能发现」→ EDUSRC 忽略（规则 7），**全程匿名最佳**。

### 14. 信息泄露（.git / 备份 / 配置 / 云存储 / JS）

- **最大范围**：**证明可访问 + 判断内容类型**，即停。
- **停止线**：记录「存在该类暴露面」这一个事实。
- **越界**：下载全量、翻找并留存身份证/手机号/成绩。
- ⚠️ **EDUSRC 只收录身份证和密码类信息泄露**（§3.1）。Git commit、内网 IP、域名、组织架构、枚举值表 → 判「无意义泄露」忽略，**只能当主链佐证**。

### 15. 子域接管

- **最大范围**：证明 CNAME 指向已释放的第三方服务（可 claim 状态）。
- **停止线**：证明悬空。**不要真去 claim、不要挂任何内容**。
- 越界：真的接管并部署内容（等于入侵第三方服务）。

### 16. 竞态 / 并发

- **最大范围**：自有资源（如自己的账号/自己的优惠券）**2~3 次并发**验证。
- **停止线**：证明存在竞态窗口。
- **越界**：高并发压测、打垮服务、批量并发下单。

### 17. 客户端（APP / 小程序 / 公众号）

- **最大范围**：本地逆向自己的客户端、抓**自己账号**的包、还原签名算法。
- **停止线**：证明算法/密钥可还原或接口可未授权调用。
- **越界**：破解他人客户端、分发改包、用还原的签名批量调用他人数据。
- ⚠️ 逆向第三方 SDK 属反爬对抗范畴，**不交**。

## 二、明确不挖 / 交了必被忽略的

| 类型 | 原因 |
|------|------|
| CORS | 本技能永久不挖（`cors-vuln-report-priority`） |
| Self-XSS、需 MITM、无敏感操作的 CSRF、无敏感信息的 JSON Hijacking、钓鱼 | EDUSRC 忽略规则 8~12 |
| 纯扫描器结果、无利用方法 | 忽略规则 13，必须手工验证 + 完整利用链 |
| DoS / 服务不可用（全站 501/502、nginx 配置异常） | 忽略规则 15 / 判「非安全漏洞」 |
| 互联网已公开的 Nday、已交 CNVD 的重复 | 忽略规则 4~5，提交前查重 |
| 需管理员登录才能发现 | 忽略规则 7 |
| 国产静态 WAF 的「绕过」本身 | 不是漏洞，且采指纹需发载荷（见 `waf-bypass.md` §9.4） |

## 三、一句话版本

> **能读就不写，能证明就不利用，能用自己的账号就不碰别人的，看到真实敏感数据就停手打码。**
> 报告的价值来自「证明存在 + 说清危害」，不是来自「我把洞打得多深」。
