# 各类漏洞的最大测试范围（无害化验证边界）

> **核心：最大测试范围 = 证明漏洞存在所需的最小操作。**
> 能查库名就不查表，能查表名就不查字段，能执行 `id` 就不执行第二条命令，能读一行就不读整个文件，能进入页面就不点任何按钮。
> **评级看的是漏洞本身的潜在危害，不是你实际挖到了多少数据。**
> 依据：`vuln-report-format.md` §3.3（EDUSRC 忽略规则）、`SKILL.md` 安全红线、`security-research-context.md`。

> **2026-09-16 全文重写**（依据 EDUSRC 无害化验证口径）。以下三处相对旧版**收紧**，旧文若冲突以本文件为准：
> ① **SSRF 不得读取云元数据**（拿临时凭证 = 实质接管云资源），改用 `127.0.0.1` / 单端口 / DNSLog 证明
> ② **越权能进入即可**，不再要求「读到一条数据」
> ③ **文件上传测试后必须立即删除**
> 已同步修订冲突旧文：`dig-scope-workflow.md` §SSRF 探针行、`src-value-hunting.md` §SSRF 行、`researcher-blackbox-whitebox.md` §SSRF 行、`知识库/agent-tool-exec-test.md`、`知识库/http-host-header-test.md`。

## 零、先确认范围（不成立就别动手）

**有奖励的范围**：教育部、人社部、中科院、各级教育局/人社局、各级主管学校/技校、教育相关软件。
**范围外无奖励**。拿不准归属先查收录名单，不猜。

## 一、通用红线（所有类型适用）

1. **不拖库** —— 不查询、不导出、不留存个人/业务敏感数据
2. **不篡改** —— 不增不删不改数据；确需改测试数据先获授权
3. **不影响业务** —— 不大规模扫描、不并发、不 DoS
4. **不横向** —— 拿到权限后不扫内网、不设跳板、不代理
5. **不留后门** —— 测试文件 / Webshell / 账号 / 计划任务，用完立即删除
6. **不泄露** —— 不泄给无关人员、不一洞多投
7. **不牟利** —— 支付类严禁真实交易与获利
8. **不登出** —— 拿到登录态后全程禁止 `/logout`、`/revoke`，不测「退出后会话还有效」

## 二、注入类

### SQL 注入
- **最大验证**：`union select` 查 `database()` / `version()` / `current_user()` / `information_schema.tables`，拿到**库名、表名、字段名**即可证明可执行 SQL。
- **禁止**：`select * from user`；查手机号、身份证、密码、订单等个人/业务数据；拖库；批量导出。
- **报告**：只截库/表/字段名，写明「未查询、导出、留存任何敏感数据」。
- **评级**：能查大量敏感数据 → 严重；普通系统可获取用户身份 → 高危；有限制条件 → 中危。

### 命令注入 / RCE
- **最大验证**：**仅一条**无害命令 —— `id`、`whoami`、`hostname`、`uname -a`，截图输出证明权限。
- **禁止**：反弹 Shell、写 Webshell、后门、读业务源码与数据库配置、内网扫描、跳板代理、增删改文件。
- **报告**：写明「仅执行一条无害命令，未做持久化或横向操作」。
- **评级**：通常严重（9~10）。

### 代码执行 / 反序列化
- **最大验证**：执行简单运算（`1+1`）或无害命令（`id`）证明可执行代码。
- ⚠️ **`phpinfo()` 要谨慎** —— 它会泄露完整配置（路径、密钥、环境变量），**等同信息泄露**。优先用 `1+1` 或 `id`。
- **禁止**：执行系统命令后继续深入、写文件、反弹 Shell。
- **报告**：只证明执行逻辑存在。

### SSTI（模板注入）
- **最大验证**：输入 `{{7*7}}` 返回 `49`，证明模板可解析。
- **禁止**：执行系统命令、读文件、反弹 Shell。
- **报告**：截运算结果即可。

### XXE
- **最大验证**：读一个无害系统文件（如 `/etc/passwd` 的 root 行），证明可读文件。
- **禁止**：读业务源码、数据库配置、批量文件；发起内网请求。
- **报告**：只截一行无害内容。

## 三、文件类

### 任意文件读取 / 下载
- **最大验证**：读 `/etc/passwd`、`web.config` 等证明存在，**只截关键片段**。
- **禁止**：批量下载全站文件、下载业务数据、留存或外传内容。

### 文件上传
- **最大验证**：上传**无害证明文件**（如 `<?php echo 123; ?>`），证明可解析执行 —— **测试后立即删除**。
- **禁止**：Webshell、木马、后门；含 `eval`/`system` 等控制性代码的文件。**即使删掉也不许传真实木马**。
- **报告**：写明「上传无害验证文件，已删除，未留后门」。
- 无法证明解析时：停在「上传成功 + 路径可访问」，如实写「未验证解析」。

### 文件包含
- **最大验证**：包含一个无害系统文件或显示简单输出，证明包含逻辑存在。
- **禁止**：包含业务源码、日志文件、敏感配置；结合上传 getshell。

### 目录遍历
- **最大验证**：读一个无害文件证明可穿越目录。
- **禁止**：遍历全站、下载敏感文件。

### 目录列表（Directory Listing，配置缺陷，≠ 目录遍历）
- **是什么**：访问无默认首页的目录，服务器返回文件列表页（Apache `Index of /`、Nginx `autoindex on`、IIS 目录浏览）。属**配置错误 + 信息泄露**，不是遍历漏洞。
- **最大验证**：对疑似目录路径（如 `/upload/` `/static/` `/backup/` `/assets/` `/www/`）发**单个 GET**，返回 `<title>Index of ...</title>` 或文件列表即确认。**只截列表、记录暴露了哪些文件名/子目录**。
- **禁止**：逐层点进去下载文件、翻遍全目录（那是「目录遍历 + 批量下载」，越线）；把列表里的备份/配置文件下载留存。
- ⚠️ 列表里若出现 `.env` / `.sql` / `config.php` / `web.bak` / 后台相关手册（如 `admin-guide.pdf`、`部署说明.md`、`初始化文档`）→ 升级为「敏感文件暴露」，按 §八 处理并报告（目录列表 + 敏感文件，可串联）。

## 四、权限类

### 越权 / 水平权限
- **最大验证**：用 A 用户访问 B 用户的页面或功能，**证明能进入即停**。
- **禁止**：查看、导出、留存 B 的个人信息与业务数据；修改 B 的数据。
- ⚠️ **若平台要求证明数据归属**（常见驳回理由「无法证明是越权」）：用**两个自有账号**做 A→B 差分，**读自己的数据**即可，不要去读他人真实数据。
- **报告**：截访问成功页面，写明「仅证明越权逻辑，未获取任何用户数据」。

### 未授权访问
- **最大验证**：直接访问后台页面/接口，证明无需认证即可进入。
- **禁止**：操作后台功能、增删改数据、查看敏感信息。
- ⚠️ 只开 health/info 的 Actuator、只渲染枚举值表的页面 → 判「无意义信息泄露」忽略，**只能当主链佐证**。
- ⚠️ **重点手法 · 3xx 响应体泄露后台（后置鉴权缺陷）**：很多后台**先把页面 HTML 渲染进响应体、再发 302/301 跳到 /login**——浏览器自动跳走看不到，但**响应体已随包发出**，抓包/读 body 就能看到管理员界面、管理员用户名、甚至「重置密码」表单。**确认方式 = 对 `/admin/` `/manage/` `/backend/` `/sys/` 等路径发单个 GET，直接看 301/302 的 body 是否含后台签名**（本技能 `fingerprint_markers.py` 已加 `未授权后台泄露 · *` 判据，classify 命中即报）。**仅一次请求、在授权内**。**报告只截 body 关键片段，绝对不实际提交任何重置/修改请求**（提交 = 篡改/越权，硬禁）。

### 权限绕过
- **最大验证**：绕过认证进入管理后台，证明绕过逻辑存在。
- **禁止**：在后台执行任何操作、查看敏感数据。
- ⚠️ 「需管理员登录才能发现」→ **被忽略**，全程匿名最佳。

### 弱口令
- **最大验证**：用弱口令**登录成功即截图**。
- **禁止**：登录后查看/修改/删除任何数据；**禁止批量爆破**。
- **报告**：写明仅验证登录、未操作业务。

### 密码修改 / 账号接管（ATO）
- **最大验证**：证明可修改任意账号密码或绕过验证 —— **不要实际修改真实用户密码**，用自己注册的测试账号验证。
- **禁止**：修改他人密码、接管他人账号。
- **定级纪律**：闭环未打通（改密页有服务端会话校验）→ **如实写「未完成账号接管」**，把「若 X 成立可提级」列为待验证假设。宁可中危，不虚报严重。

## 五、服务端请求类

### SSRF
- **最大验证**：请求一个无害内网地址（如 `http://127.0.0.1:80`）或外部可控地址，证明可发起请求。
- **禁止**：扫描内网端口、**读取云元数据（`169.254.169.254` 拿临时凭证 = 实质接管云资源）**、攻击内网系统、读业务文件。
- **报告**：只证明请求能力，不深入内网。
- ⚠️ **WebVPN 类入口只验证不挖** —— 证明内网可达即停手。

## 六、客户端类

### XSS
- **最大验证**：`alert(1)` 或 `console.log(1)` 证明脚本执行（**自己账号**）。
- **禁止**：窃取 Cookie/会话、键盘记录、持久化 XSS、钓鱼。
- ⚠️ **Self-XSS 不收**。盲打要有回连证明才交。

### CSRF
- **最大验证**：构造 PoC 证明无 Token 可发起请求 —— **不实际修改数据**。确需修改先联系平台授权。
- **禁止**：实际改密码、删数据、转账。
- ⚠️ **无敏感操作的 CSRF 不收**。

### 点击劫持
- **最大验证**：证明页面可被 iframe 嵌入。
- **禁止**：实际诱导用户操作。
- ⚠️ 评级低，**需存在敏感操作才可能收**，谨慎投入时间。

### 客户端（APP / 小程序 / 公众号）
- **最大验证**：本地逆向自己的客户端、抓**自己账号**的包、还原签名算法。
- **禁止**：破解他人客户端、分发改包、用还原的签名批量调他人数据。
- ⚠️ 逆向第三方 SDK 属反爬对抗，**不交**。

## 七、逻辑类

### 支付逻辑
- **最大验证**：证明支付逻辑缺陷 —— **禁止真实交易**。
- **禁止**：利用漏洞牟利、真实下单、改金额后实际支付。
- **报告必须写清**：测试账户、测试步骤、**未造成资金损失**。
- ⚠️ 最容易出事的一类：宁可只报「参数可篡改」，也别真下单。

### 业务逻辑绕过（0 元购 / 重复领取 / 限购）
- **最大验证**：证明可绕过限制 —— **不实际获取利益**，不造成经济损失。
- **禁止**：实际领取、下单、提现。

### 验证码 / 短信 / 邮件
- **最大验证**：用**自己的 1~2 个号**测 3~5 次，证明可爆破 / 可无限发 / 验证码响应包回显。
- **禁止**：轰炸他人、大量调用、用他人号码。
- 看到验证码回显 = 直接中危以上，截图即停。

### 竞态 / 并发
- **最大验证**：自有资源 2~3 次并发验证。
- **禁止**：高并发压测、打垮服务、批量并发下单。

## 八、信息泄露类

- **最大验证**：证明存在泄露（配置、密钥、源码），**只截关键部分**。
- **禁止**：批量下载、传播、利用。
- ⚠️ **平台只收身份证与密码类**；Git commit、内网 IP、域名、组织架构、枚举值表 → 判「无意义泄露」忽略，**只能当主链佐证**。
- ⚠️ 定性纪律：本质是「密码找回流程身份校验失效」的，**必须按认证逻辑缺陷写**，写「敏感信息泄露」会按口径拒收。
- ⚠️ **可识别形态 · 重定向体泄露**：`3xx` 响应体里夹带后台管理页面、管理员用户名、重置密码接口——属「访问控制后置 + 信息泄露」，**值得报**（管理员用户名泄露 + 重置接口暴露）。注意：这类泄露**在 302 body 里**，不在 200 页面里，普通爬虫/浏览器看不到，必须读原始响应体才抓得到。
- ⚠️ **配置错误类信息泄露 · 速查（单 GET / 被动即可确认，勿用目录爆破）**：
  - **Debug 模式**：Django/Laravel/Flask/ASP.NET 未关 Debug，出错返回堆栈 / 环境变量 / `SECRET_KEY` / DB 连接串。确认 = 对不存在的路由发**单个 GET** 触发 500，看 body。**只证明存在、截关键片段，绝对不复制/留存密钥本身**（复制密钥 = 留存敏感数据，硬禁）。
  - **敏感文件直链**（无需列表，已知文件名直接 GET）：`.env`、`.git/config`+`.git/HEAD`（可恢复源码）、`phpinfo.php`/`info.php`、`web.config`/`nginx.conf`+`.bak`/`.old`、`swagger.json`/`api-docs`（未授权 API 文档）、`robots.txt`/`sitemap.xml`（暴露后台/敏感路径，**优先读这两个做路径发现**）。
  - **编辑器/系统残留**：`.DS_Store`（macOS，泄露目录结构，等同迷你列表）、`.swp`/`.swo`（Vim 源码临时文件）、`Thumbs.db`、`test.php`/`old_index.html` 部署残留。
  - **源码/注释泄露**：HTML 注释藏口令（`// admin password is ...`）、JS 硬编码 API Key / 内网地址。
  - **对象存储公开可读**：S3/OSS/COS 配公开 → 列桶下载备份/照片/日志。**仅在 `*.edu.cn` 范围内查，不桶名爆破**。
  - 上述多数已有专文 `知识库/artifact-intel-guide.md`（.env / lock / SW 等），本处只补「配置错误」视角与确认边界。
- ⚠️ **明确不吸收的发现手法**：原文推荐的 **目录爆破（Dirsearch / Gobuster / ffuf 扫常见路径）** 与 **默认口令库批量扫描** 违反本技能「禁止目录爆破 / 不爆破 / 低频单请求」红线——**路径发现只靠被动源**（robots.txt、sitemap.xml、JS/`env.js`/`baseURL`、README、页面注释、证书透明日志 `crt.sh`），不靠暴力枚举。默认口令只在「已拿到且确定是该产品的登录口」试 1 次已知默认组合（如 `admin/admin`），不扫字典。
- ⚠️ **平台通常不收（单独提交会被拒）**：① 缺安全响应头（X-Frame-Options/CSP/HSTS/nosniff）—— 仅当串成点击劫持/XSS 等可打点才收；② CORS 宽松 —— 本技能永久不挖（见 §另加）；③ 纯「目录列表但里面只有静态资源、无敏感文件」—— 价值低，需指出暴露了什么才算。

### 子域接管
- **最大验证**：证明 CNAME 指向已释放的第三方服务（可 claim 状态）。
- **禁止**：**真去 claim、挂任何内容**（等于入侵第三方服务）。

2. 虚假漏洞
3. 已公开、或已被其他白帽子提交过（**提交前查重**）
4. 交本平台后又交其他平台
5. 无详细链接 / 截图 / 利用方法

14. 拒绝服务
15. 已公开利用方式的通用型漏洞

## 十一、3xx / 403 的「继续挖掘方法」哪些本技能**不吸收**

网上常见「3xx 跟过去、403 分层绕过」教程，多数混了**红队绕过目标防护**的手法，与本技能的 edu SRC 白帽定位（被动 + 单请求低频 + 不绕 WAF + 不爆破）冲突。**明确分界**：

- ✅ **吸收的**：① 3xx 自动跟随（默认行为）；② **读 3xx 响应体**（后台 HTML 可能塞在 302 body 里，见 §四/§八）；③ 307/308 保留原请求方法、301/302 转 GET（构造重放时别弄错）；④ 403 第一层基础伪装（真实 UA / Referer / Accept / 维持 Session-Cookie / 加随机延迟）—— 这本就是我们探活的基本姿势，不算「绕过」。
- ❌ **不吸收的（红队绕过手法，越红线）**：
  - **代理 IP 轮换 / 住宅代理 / IP 池** —— 为躲过目标 IP 封禁而换源。本技能禁止对非自有资产高频重试，被 403/封 IP 就停，**不换 IP 硬刚**。
  - **无头浏览器 + TLS/JA3 指纹伪造**（Playwright/Puppeteer 改指纹过 Cloudflare 等 JS 质询）—— 属绕过对方抗 bot 防护，不在授权范围。
  - **验证码识别服务 / 人工打码** —— 绕过人机验证，越线。
  - **任何为「继续挖掘」而提高并发、降延迟、伪造客户端指纹** 的行为 —— 与「不影响业务 / 不绕 WAF / 不爆破」直接冲突。
  - **目录爆破（Dirsearch / Gobuster / ffuf 扫常见路径、扫桶名）** —— 违反「禁止目录爆破」。路径发现只靠被动源（robots.txt / sitemap.xml / JS `env.js` `baseURL` / README / 页面注释 / `crt.sh` 证书日志），不靠暴力枚举。`.DS_Store` / `test.php` / `web.bak` 这类**已知文件名**的单次 GET 是可做的；「猜几万个路径」不可做。
  - **默认口令字典扫描** —— 违反「不爆破」。只在「已拿到且确定是该产品的登录口」试 **1 次已知默认组合**（如 `admin/admin`、`tomcat/tomcat`），不扫弱口令字典。

> 原则：**遇到 403 的正确动作是停下、换路径、或换目标，不是换 IP 接着打。** 被拦说明对方有防护——与其对抗，不如回到「被动 + 单请求」的合规打法，或走「自有靶机」路线验证（见 `waf-bypass.md` §9.4）。信息泄露类同理：**靠被动源找路径与文件，不靠爆破枚举**——目录列表/Debug/.env 这些大多一次 GET 就能确认，根本不需要扫描器。
